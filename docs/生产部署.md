# 光域造景 · 生产 Docker 部署

在 Linux 服务器上用 Docker Compose 长期运行 Web 服务。部署物是仓库根目录的 `Dockerfile` 与 `docker-compose.yml`，入口为 `python web_app.py`，容器内监听 `8090`。

## 1. 服务器要求

| 项目 | 要求 |
| --- | --- |
| 系统 | Ubuntu 22.04 或同类 Linux |
| Docker | Docker Engine 24 及以上 |
| Compose | Docker Compose 插件 v2（命令为 `docker compose`） |
| CPU / 内存 | 演示模式建议 4 核、8 GB |
| 磁盘 | 系统盘预留 20 GB 以上，输出目录单独挂载更好 |
| 网络 | 安全组或防火墙放行业务端口（默认 `8090`） |
| GPU | 演示模式不需要。完整三维生成需要 NVIDIA GPU、驱动与 NVIDIA Container Toolkit |

安装 Docker 后确认：

```bash
docker version
docker compose version
```

## 2. 放置代码

将发布包解压到固定目录，例如 `/opt/guang-yu-zao-jing`。后续命令都在该目录执行。目录中需要包含：

- `Dockerfile`
- `docker-compose.yml`
- `web_app.py`
- `webui/`
- `requirements-web.txt`
- `examples/`
- `assets/`

创建持久化目录：

```bash
mkdir -p data outputs results
```

## 3. 生产配置

默认可直接使用仓库中的 `docker-compose.yml`：

- 服务名：`hzq-dreamer`
- 容器名：`hzq-lucid-dreamer`
- 端口：`8090:8090`
- 环境变量：`LD_DEMO_MODE=1`
- 卷：`data`、`outputs`、`results`、`examples`
- 重启：`unless-stopped`

对外只暴露一个端口。建议由宿主机防火墙或前置反向代理限制来源网段。应用本身打开即可使用，没有账号体系，能访问该端口的人都可以操作生成与查看历史。

如需改端口，只改宿主机侧，例如 `"18090:8090"`，容器内仍保持 `8090`。

### 演示模式与完整算力

| `LD_DEMO_MODE` | 行为 |
| --- | --- |
| `1` | 当前镜像的默认值。生成预览图、演示动画，并写入任务历史 |
| `0` | 加载 `luciddreamer.py` 中的完整三维引擎，计算固定在 CUDA 上 |

条件未满足时服务仍会启动，并自动退回演示模式。工作台引擎状态会写出加载失败的原因。

`LD_DEMO_MODE=0` 需要同时具备：

**硬件与容器运行时**

- NVIDIA GPU，驱动已安装，显存建议 16 GB 及以上
- 服务器安装 [NVIDIA Container Toolkit](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/install-guide.html)，`nvidia-smi` 在宿主机可用
- Compose 把 GPU 交给容器（见下方片段）

**镜像**

现有 `Dockerfile` 基于 `python:3.9-slim-bookworm`，只装 `requirements-web.txt`，只复制 Web 文件。完整模式的镜像还要：

- 复制 `luciddreamer.py`、`arguments.py`、`scene/`、`gaussian_renderer/`、`utils/`、`cameras/`、`ZoeDepth/`、`submodules/`
- 安装 `libglm-dev`
- 安装 `requirements.txt`，其中 `torch==2.0.1` 必须是 CUDA 轮子
- 其余包：`torchvision`、`diffusers==0.23.1`、`peft==0.6.2`、`timm==0.6.7`、`open3d`、`opencv-python`、`scipy`、`plyfile`、`imageio[ffmpeg]`、`Pillow`、`numpy`
- 使用与 PyTorch 匹配的 `nvcc` 编译：

```bash
pip install submodules/simple-knn
pip install submodules/depth-diff-gaussian-rasterization-min
```

**权重（首次启动自动下载）**

服务器出网需能访问 Hugging Face 与 GitHub。权重缓存建议预留 30 GB，并挂载到卷上。

| 用途 | 来源 |
| --- | --- |
| 启动时的默认扩散模型 | `runwayml/stable-diffusion-inpainting`，revision `fp16` |
| 界面「标准模型 SD1.5」再次加载 | `stablediffusion/SD1-5`，revision `fp16` |
| 炽热驱动 / 写实视觉 / 卡通皮克斯 | `stablediffusion/Blazing Drive V11m`、`stablediffusion/Realistic Vision V5.1`、`stablediffusion/RealCartoon-Pixar V5`，均为 `fp16` |
| 后三个模型的 ControlNet | `lllyasviel/control_v11p_sd15_inpaint` |
| 后三个模型的 LaMa | `big-lama.pt` |
| 深度 | `ZoeDepth` 本地 hub 的 `ZoeD_N`（`pretrained=True`），下载 `ZoeD_M12_N.pt` 与 MiDaS `DPT_BEiT_L_384` |

**Compose 片段**

```yaml
environment:
  - LD_DEMO_MODE=0
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: 1
          capabilities: [gpu]
```

启动后工作台应为「完整算力」，引擎状态为「三维生成引擎已加载」。

## 4. 构建并启动

```bash
cd /opt/guang-yu-zao-jing
docker compose up -d --build
docker compose ps
docker compose logs -f --tail 100
```

确认容器状态为 `Up`，且日志显示服务已在 `8090` 启动。

本机探活：

```bash
curl -I http://127.0.0.1:8090
```

返回 HTTP 200 后，从办公网访问：

```text
http://<服务器IP>:8090
```

## 5. 反向代理（可选）

若要通过 80/443 域名访问，由 Nginx 把请求转到 `127.0.0.1:8090`。Gradio 使用 HTTP 与 WebSocket，代理需要同时转发这两种流量，并加大上传体积与超时，以便传参考图和结果文件。示例：

```nginx
server {
    listen 80;
    server_name dream.example.com;
    client_max_body_size 100m;

    location / {
        proxy_pass http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 600s;
    }
}
```

使用域名后，把安全组里的 `8090` 限制为本机，只对公网开放 80/443。

## 6. 数据与备份

需要备份的目录：

- `data/`：任务历史
- `outputs/`：生成产物
- `results/`：渲染产物
- `examples/`：若线上改过示例图，一并备份

示例：

```bash
tar -czf guangyu-data-$(date +%F).tar.gz data outputs results
```

恢复时先 `docker compose stop`，解压覆盖对应目录，再 `docker compose start`。

## 7. 更新发布

1. 上传新代码，保留服务器上的 `data/`、`outputs/`、`results/`。
2. 在项目目录执行：

```bash
docker compose up -d --build
```

Compose 会重建镜像并替换容器。挂载卷里的历史和结果仍在宿主机上。

回退时检出上一版代码，再次执行 `docker compose up -d --build`。

## 8. 日常运维

```bash
docker compose ps
docker compose logs -f --tail 200
docker compose restart
docker compose down
docker stats hzq-lucid-dreamer
```

`docker compose down` 只删除容器，不删除挂载目录。

## 9. 上线检查

- `docker compose ps` 中容器为运行中，重启策略为 `unless-stopped`
- `curl -I http://127.0.0.1:8090` 返回 200
- 浏览器能打开工作台，六张统计卡有数字
- 示例图库能预览一张示例图
- 场景生成能跑通一次，任务历史出现新编号
- `data/history.json` 在宿主机上能看到更新
