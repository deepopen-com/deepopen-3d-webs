# 光域造景 · 本地 Docker 部署

在本机用 Docker 启动 Web 服务，默认是演示模式：页面、示例、任务历史和预览生成可以完整走通。完整三维高斯生成需要 GPU 与模型权重，见 [生产部署](生产部署.md)。

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11、macOS 或 Linux |
| Docker | Docker Engine 24 及以上，并带 Compose 插件（`docker compose`） |
| 内存 | 建议 8 GB 及以上 |
| 磁盘 | 镜像与示例素材约数 GB，输出目录按使用量增长 |
| 端口 | 本机 `8090` 未被占用 |

Windows 请安装 Docker Desktop，并确认它处于运行状态。

## 2. 获取代码

将仓库放到本机目录，下文以项目根目录为准。根目录下应能看到 `Dockerfile`、`docker-compose.yml`、`web_app.py`、`webui/`、`examples/`、`assets/`。

## 3. 启动

在项目根目录执行：

```bash
docker compose up -d --build
```

首次构建会拉取 `python:3.9-slim-bookworm`，并按 `requirements-web.txt` 安装 Gradio 等 Web 依赖，耗时取决于网络。

查看状态：

```bash
docker compose ps
docker compose logs -f
```

日志中出现 Gradio 监听 `0.0.0.0:8090` 后即可访问。

## 4. 访问

浏览器打开：

```text
http://127.0.0.1:8090
```

本系统打开即可使用，没有登录账号。

## 5. 默认运行方式

`docker-compose.yml` 已设置：

- 容器名：`hzq-lucid-dreamer`
- 镜像名：`hzq-lucid-dreamer:latest`
- 端口：宿主机 `8090` → 容器 `8090`
- `LD_DEMO_MODE=1`：演示模式
- 重启策略：`unless-stopped`

演示模式下可以上传图片、载入示例、生成预览图与演示动画，并写入任务历史。当前镜像基于 CPU 版 Python 精简镜像，适合本地页面联调与演示闭环。

## 5.1 `LD_DEMO_MODE=0` 需要的条件

设为 `0` 后，服务会加载 `luciddreamer.py` 里的完整引擎。计算全部放在 CUDA 上。下面任一项缺失时，页面仍能打开，并自动退回演示模式，工作台的引擎状态会写出失败原因。

**硬件**

- NVIDIA 显卡，驱动可用
- 显存建议 16 GB 及以上。默认会同时把扩散模型（fp16）和 ZoeDepth 放到 GPU 上，随后还要训练高斯
- Docker Desktop 启用 GPU 支持（Windows 需要 WSL2 后端和 NVIDIA 驱动）

**镜像内容**

仓库自带的 `Dockerfile` 只安装 `requirements-web.txt`，并只复制 `web_app.py`、`webui/`、`examples/`、`assets/`。完整模式还要把这些放进镜像：

- `luciddreamer.py`、`arguments.py`
- `scene/`、`gaussian_renderer/`、`utils/`、`cameras/`
- `ZoeDepth/`、`submodules/`

并安装 `requirements.txt`：

- `torch==2.0.1` 的 CUDA 轮子（CPU 版无法加载）
- `torchvision`、`diffusers==0.23.1`、`peft==0.6.2`、`timm==0.6.7`
- `open3d`、`opencv-python`、`scipy`、`plyfile`、`imageio[ffmpeg]`、`Pillow`、`numpy`

系统包需要 `libglm-dev`（见 `packages.txt`）。再用与 PyTorch 匹配的 `nvcc` 编译两个扩展：

```bash
pip install submodules/simple-knn
pip install submodules/depth-diff-gaussian-rasterization-min
```

**权重**

引擎初始化时会自行下载，机器要能访问 Hugging Face 和 GitHub。权重缓存建议预留 30 GB 以上。

| 用途 | 来源 |
| --- | --- |
| 默认扩散（启动即加载） | `runwayml/stable-diffusion-inpainting`，revision `fp16` |
| 切回「标准模型 SD1.5」 | `stablediffusion/SD1-5`，revision `fp16` |
| 炽热驱动 V11m / 写实视觉 V5.1 / 卡通皮克斯 V5 | `stablediffusion/<模型英文名>`，revision `fp16` |
| 上述三个模型共用的修补网络 | `lllyasviel/control_v11p_sd15_inpaint` |
| 上述三个模型共用的修复 | LaMa `big-lama.pt` |
| 深度 | 本地 `ZoeDepth` 的 `ZoeD_N`（`pretrained=True`），下载 `ZoeD_M12_N.pt` 和 MiDaS `DPT_BEiT_L_384` |

界面上的模型英文名是 `Blazing Drive V11m`、`Realistic Vision V5.1`、`RealCartoon-Pixar V5`。

**编排**

`docker-compose.yml` 在完整模式时改为：

```yaml
environment:
  - LD_DEMO_MODE=0
deploy:
  resources:
    reservations:
      devices:
        - driver: nvidia
          count: 1
          capabilities: [gpu]
```

把 Hugging Face 与 `torch.hub` 缓存目录做成卷，重建容器后不必重新下载。

工作台显示「完整算力」，且引擎状态为「三维生成引擎已加载」，即表示条件已满足。

## 6. 数据目录

下列目录挂载到容器内，删容器不会丢掉这些数据：

| 本机目录 | 容器路径 | 内容 |
| --- | --- | --- |
| `./data` | `/app/data` | 任务历史 `history.json` |
| `./outputs` | `/app/outputs` | 生成结果 |
| `./results` | `/app/results` | 渲染结果 |
| `./examples` | `/app/examples` | 示例图片与提示词 |

修改示例图后无需重建镜像，重启容器即可：

```bash
docker compose restart
```

修改 `webui/`、`Dockerfile` 或依赖后需要重新构建：

```bash
docker compose up -d --build
```

## 7. 停止与清理

停止并移除容器，保留镜像与本机数据目录：

```bash
docker compose down
```

连同本地镜像一起删除：

```bash
docker compose down --rmi local
```

## 8. 常见问题

**8090 打不开**

确认容器为 `running`：`docker compose ps`。若端口被占用，把 `docker-compose.yml` 里的 `"8090:8090"` 改成 `"18090:8090"`，然后访问 `http://127.0.0.1:18090`。

**构建时 pip 很慢**

镜像内已使用清华 PyPI 源。仍失败时检查本机能否访问外网，然后重新执行 `docker compose build --no-cache`。

**页面能开，但没有真实三维模型**

默认 `LD_DEMO_MODE=1`，得到的是演示预览。要真实高斯和深度，按第 5.1 节准备 GPU、CUDA 版依赖、扩展模块和权重，再把该变量设为 `0`。
